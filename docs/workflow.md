# 从一个念头到一部可以交给读者的小说

先弄清这次要交付什么。用户想比较两种写法，就让两种写法的得失可比较。用户委托完成一卷，就按约定范围推进到卷末。已有作品从现稿接手，保留可用的章节、设定和习惯，只补会影响眼前任务的资料。下列完成条件供主创自行检查。

## 接住委托

文字或语音转写很零散时，先用一两句还原用户最在意的画面、关系或情绪。人名同音、否定词和时间先后会改变剧情时，单独核对那处歧义。方向明确就动手。可逆的小选择自行处理。影响核心方向又无法推定的选择，通常一次集中问一至三个问题，给出可想象其后果的选项与建议。重要的暂定判断注明理由和适用范围。

明确的新作委托已经授权立项。先查唯一作品索引与现存目录，避免并行撞号，按模板说明登记所选作品。单纯讨论的创意留在对话中，有明确归属的备选可收入作品的 `memory/ideas.md`。接到“继续”，由当前对话和该作品的状态辨认对象与终点。没有约定篇幅时，交付下一项完整成果，如一章或一份可用章纲。[作品索引](../novels/README.md) · [实例化说明](../templates/README.md)

## 八个阶段的交付尺度

| 阶段 | 主创怎样推进 | 交付前问自己 |
| --- | --- | --- |
| 创意接收 | 保留原意和必保元素，将读者、期待读感、篇幅倾向、内容边界与关键未知写入简报。 | 这份复述还能让用户认出最初想写的东西吗？ |
| 头脑风暴 | 有分岔时给两三个真正不同的方向，写明各自会让谁承担什么后果、读者会期待什么，并说明推荐理由。 | 已选方向或工作假设，足以支持用户委托的下一步吗？ |
| 核心框架 | 建立简报、完整内部梗概、人物关系、行动所需的世界规则与文风依据。在梗概中说清已有的结局构想。长连载可先确定阶段终点，将远期走向标为假设。 | 关键选择是怎样被欲望、处境和代价逼出来的？群像各线如何在共同事件或观察中相互照亮？ |
| 章节规划 | 总纲保留全书或阶段路线。细化眼前数章的行动、选择、信息释放、情绪累积及收尾。给重要承诺、伏笔和副线安排落点。 | 目标章从哪里接起？人物此刻能知道什么？读者过了这章会多在意什么？ |
| 章节创作 | 简报、故事方向、涉及的人物与规则、文风和近期章纲足以支撑目标章后，写成约定篇幅的完整正文。先核对行动及情感的来路，再做局部语言复核。 | 这一章推进或加深了哪段体验？静观和停顿是否值得留下？视角、声音、前后事实能否接上？ |
| 阶段回看 | 转折或卷末回看人物曾作的选择、读者已获的信息和主副线间的回响。将具体问题落实到有关章节或后续计划。 | 开头许下的阅读承诺积累到哪一步？一个重要揭示是否有可回认的依据？ |
| 全书修订 | 通读并先修结构因果，再修人物与关系，继而处理场景取舍和节奏、语言对白，最后复核连续性和校对。剪去一场戏后重查依赖它的决定、情感和信息。 | 主要问题在当前稿里解决了吗？删改之后能否连贯地读完整部作品？ |
| 定稿交接 | 按指定版本交阅读稿、概要、人物资料和开放线索结算。写清有意的留白及适用范围。“用户认可定稿”须有相应决定。 | 读者拿到的文本能否按正确顺序完整阅读？编辑能否找到对应来源章？ |

试写只需先确定与片段有关的视角、情境和声音。局部示范可以直接交付。探索稿是否进入当前稿，另据采用决定处理。短篇可合并工作步骤。非线性叙事可在规划时分别记叙述次序与事件次序。方法随作品而选。[故事方法](story-method.md) · [语言复核](prose-style.md)

## 审稿与反馈

从会引起返工的问题入手。每条有行动价值的意见带上来源章、稿次和具体段落，再写“读到了什么、哪里受阻、会损害什么、怎样改或为何保留”。分清可核实的事实矛盾、影响阅读的叙事问题与风格偏好。一次有针对性的复核达成目的即可。值得追踪的问题按作品 `reviews/README.md` 的格式存放。

读到“太平”“像流水账”一类反馈，先回到被指出的段落。举个教学示例。争执之后，两人的下一步安排一如既往，“不够狠”可能指选择缺乏代价。若两人已经分开，段尾却又把双方心情解释一遍，问题可能在叙述距离。说明判断依据。两种解读会带来截然不同的大改时，用具体选项或短段试改校准。反馈落在一句，只改那一句及必要衔接。改变整部作品的视角，则同步文风依据和受影响的章节。跨作品偏好以用户明确表述为据。

开篇、关键揭示或重大重写后，可做首次阅读体验审读。把截至目标位置的正文和读者可见的前情交给独立审读者，先请其指出在哪一句明白了什么、期待什么、何处情绪转变、哪里愿意读下去或失去方向。主创取得意见后再对照后文，分清“读者知道自己在等答案”和“缺少理解眼前行动所需的条件”。无信息隔离时说明审读者已知的后续。记录中区分 AI 模拟、编辑间共识和真实读者反馈。选择这项检查取决于本轮问题。

## 分工与并发

主创掌握创作意图、正文声音和最终写入。比较两条路线，可请故事策划独立推演因果与代价。关系转折难以置信，可请人物与情绪编辑追溯动机、语气变化和情感积累。揭示节点交给连续性编辑核对规则、时序、人物所知、道具与伏笔。文字编辑处理明确范围内的语句和对白，保护叙事事实及有作用的形式。

派工时给出作品与目标、来源版本、最小阅读范围、允许写入的文件、返回形式。审稿通常只回传带位置的意见。同一阶段每个文件只指定一个写入者。方案比较和独立复核可以并行。下一章依赖上一章尚未写出的选择时，先完成前章并核定接续点。环境只有单一上下文时，顺序执行需要的核对，如实说明其局限。

有并发会话时，先明确各自基线及范围。需要隔离才使用分支或工作树。写回前核对文件是否被别人更新。整合后重新追踪人物为何行动、何时得知关键信息以及改动波及的后章。两条编辑意见冲突时，由主创据实际段落权衡收益与损失，保留有充分作用的原句。

## 保存、汇编与交接

一次实质修订先登记范围、基线、待同步项和可恢复旧稿，再保存正文或基础设定，校正派生资料，最后推进状态基线。中断后先补齐依赖。工作稿经主创必要复核即可纳入当前版本。用户要求只看正文时提交清洁正文，工作记录另外维护。因客观限制只完成部分时，保存接续位置并说清剩余范围。[保存次序与恢复](context.md#跨文件保存与中断恢复)

收到整稿、合订本或阅读交付委托时，定位来源版本，依 `chapters/README.md` 的**展示顺序**逐项取对应稿次。逐章对照 ID 与范围，检查缺章、重复章、误收的探索稿、占位文字及夹进正文的审稿意见。交付 Markdown 阅读稿，在稿首或随附交接说明标明来源版本。管理摘要、人物资料与线索结算分开交。之后先修订来源章，再按同一顺序重新汇编。

已连载的作品从章节索引查已发范围与版本，判断本次承接原连载还是修订稿。内部重写早章后，原连载读者依然只知道已发表的内容。若按原连载续写，依该版本核对人物所知与读者前情。只有两条承接路径都合理且会改变正文时才澄清。实际发布依授权进行。收到改编委托，从作品的 `adaptation/README.md` 进入，先钉住小说来源版本，再允许改编有自己的结构和版本。
