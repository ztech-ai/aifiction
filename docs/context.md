# 资料归属、读取与接续

先用本轮明确的编号、标题、路径或上下文认定作品。需要查找时，打开唯一的[作品索引](../novels/README.md)。各会话独立选定目标。先查实际适用的仓库和作品指令入口，包括本目录层级可能存在的 `AGENTS.override.md`。从仓库根启动也要显式检查作品的局部约定。下文短路径均相对目标作品。

## 指令入口与容量

Codex 从项目根沿目录走到启动目录，在每一层优先选取非空的 `AGENTS.override.md`，其次是 `AGENTS.md`，其他候选名取决于配置。同级覆盖文件存在时，检查它是否接入了仍适用的项目约定。模板里的 `AGENTS.template.md` 待立项改名后使用。[Codex 项目指令说明](https://developers.openai.com/codex/guides/agents-md/)

`project_doc_max_bytes` 的官方默认值为 32,768 字节（32 KiB），按加载顺序由整条项目指令链共享。某层可能读到一半，后续层可能被跳过。扩写规则时先把细则移到专项文档；核对字节数时包括各级实际入口。该预算只管项目指令。

在当前实例的 Codex CLI 中，以两个各 20,000 字节的临时指令实测，离线提示预览保留了第一层的全部内容和第二层的前 12,768 字节。用 `codex debug prompt-input` 从仓库根预览可见完整根规则；从上级 `/workspace` 启动则未出现。从临时实例化的作品目录启动，根和作品两级指令均能完整匹配。启动目录、配置或运行时变化后，按新任务的实际加载证据判断；手动打开文件只能证明本次已读。

## 按任务取材

用目录、标题和稳定 ID 定位到段落，复用已读且未变的内容。写回前核对源文件与读取时的基线。日常任务无需加载无关作品、全量旧稿或聊天记录。全书结构重写可以按依赖扩到本作品全书。资料过长可分卷、分人物或线索，保留原入口和来源。分段读取时让场景和论据保持完整。

| 本轮任务 | 默认取用 | 何时扩读 |
| --- | --- | --- |
| 续写下一章 | 由 `README.md` 进入 `memory/state.md`。取 `bible/brief.md`、`bible/style.md` 的当前约束，`chapters/README.md` 的展示顺序、稿次及近期实际摘要，`planning/chapters.md` 的目标章与邻章计划，直接前章正文。取相关的 `bible/characters.md`、`bible/world.md` 及 `memory/continuity.md` 条目。 | 状态有欠项先恢复。动机、伏笔、所知、道具有疑问，沿条目回到来源章及相关决定。 |
| 局部语言润色 | 目标句段及足以还原语境的上下文、作品文风、人物声音、用户要求保留的内容。 | 指代、否定、潜台词或伏笔悬而未决时，补读有关原文。通常无需总纲。 |
| 修改剧情或章纲 | 目标稿次和被改内容、相关简报要求、总纲与章纲的相应部分，以及角色、规则和连续性条目。 | 向前追铺垫与动机，向后查选择的后果、何时揭示、哪些章依赖旧事实。 |
| 首次阅读体验审读 | 审读者只获截至指定位置的正文和读者可见的前情，主创留存位置与依据版本。 | 阅读体验记录完成后，主创再对照谜底、隐藏动机、计划和审读结果。已见后文时如实说明。 |

前章按章节索引中的展示顺序查，首章跳过。前章较长时，可从实际摘要进入完整的接续场景，遇到细节再补相应原文。声音、对白、物品交接等具体判断回查原句。续集或共享世界须有用户明确关联。在简报写清关联作品、来源版本、需取哪部分，以及属于同一连续性、平行版本还是仅复用创意。关联作品发生变化时，按约定版本和此次委托判断影响。

## 一条信息在哪里改

| 想查或改变的东西 | 主维护位置 | 其他资料如何跟进 |
| --- | --- | --- |
| 创作意图、读者、必保元素 | `bible/brief.md` | 改变核心取舍时在 `memory/decisions.md` 留理由和范围。 |
| 视角、叙述距离、语体、风格参照与适用范围 | `bible/style.md` | 作品指令给入口。必要摘要随来源更新。 |
| 基础人物与世界 | `bible/characters.md`、`bible/world.md` | 改人物行动边界须查相关正文。续写依赖的动态变化另带来源记入连续性。现实依据放 `research/`，注明核验状态。 |
| 未来路线与近期安排 | `bible/story.md` 管整体，`planning/chapters.md` 管近期细节 | 计划实现后由实写内容产生摘要。改掉的路线标出取代关系。 |
| 当前稿已经发生什么 | `chapters/` 中对应稿次的正文 | `chapters/README.md` 按实际展示顺序指向源文件并给出实际摘要。`memory/continuity.md` 摘取会制约后文的时序、所知、物品及线索。 |
| 本轮做到哪一步、如何接手 | `memory/state.md` | 作品 README 链接至此。阶段变化才同步仓库作品索引的阶段摘要。 |

用栏名或少量标记分清**用户决定**、**AI 工作假设**、**已采用设定**、**当前稿事实**、**未来计划**、**待选提议**和**已弃用内容**。决定条目写清谁作出、为何、影响哪里。一个设定已采用，仍可以是人物尚未知晓的真相。一句对白只能证明此人如此说过。涉及欺骗和误会，分别记录世界真相、谁知道或相信什么及其依据、读者到哪个位置能得知什么。

冲突先定位具体文件、段落、稿次及影响范围。笔误可直接修。用户明确改向，则查依赖并完成连带修改。尚未决定的核心分歧，列出两种处理会改变哪些章节、人物与阅读体验，并给出建议。未处理的影响项留在状态里。

## 跨文件保存与中断恢复

章节索引用**稳定 ID、展示顺序、标题、文件路径、稿件状态、修订标识、实际摘要**定位当前稿。未写章的实际摘要留空。已发布的范围及版本按需另记。如果读者已见旧稿，保留该基线。插章用尚未占用的 ID，调展示顺序和相邻章的衔接。改标题优先改展示名。需要改路径时同步索引与所有引用。作品编号同样保留，归档后不得回收。

1. **写前留可恢复的依据。** 跨文件交付或大改时，在 `memory/state.md` 的未同步事项登记范围、源文件与依据稿次、还需核对的下游。覆盖重要旧稿前检查实际提交能取回那一稿。重要的未提交文字需按仓库约定单独保存，对暂不能提交的旧稿保留带来源与稿次的 Markdown 快照。保存旧稿时避开无关改动。阶段性替代结局可单列并注明是否采用。
2. **先存来源，再校派生。** 保存正文或基础设定，给实质修订一个可辨识的稿次。按受影响范围更新章节索引中的实际摘要与来源稿次、连续性条目及其出处、近期或整体计划、必要的决定。检查动机、所知与揭示次序、时间线、伏笔及回收。较早一章改动时沿这些依赖向后核对。稿次可以是明确标识的未提交工作稿。引用提交号须有实际提交。
3. **状态最后结清。** 用 `memory/state.md` 简记当前任务与阶段、最近完成位置、接续所需信息、本次已核对的来源及稿次、仍欠哪项与下一步。只清除确已完成的事项，阶段变化再更新根索引。保持短摘要，旧过程交给 Git。单处勘误以实际影响为准。

重新接手时，用状态所说的基线对照涉及的源文件和章节索引，检查工作区是否出现后来变更。已提交部分可以用相应提交的差异定位，未提交部分对照本轮标记和原文。若摘要仍依据旧稿，只重建受影响的摘要与连续性等资料。若正文只写到一半，保留实写内容，标明部分完成及接续位置。若无法判断另一会话采用了哪版，先保留两边的有效修改并厘清分歧。完成核对后再续写。普通 Git 合并成功，仍需检查事件、人物和信息的依赖关系。

模板版本从作品 README 查。模板更新用于新作。旧作按任务选取所需改进，迁移时保护已有约定与资料。涉及交接时说明成果实际位于工作区、哪个提交或哪个远端分支。这些位置各有自己的保存范围。

## 桌面走查示例

以下情景供遇到相似委托时核对预期动作，均为示例。

| 输入与转折 | 主创应能走到的结果 |
| --- | --- |
| 比较两个创意，随后明确开发其中一个 | 比较时只讨论体验与代价。收到具体作品委托后查索引，给选中的一个分配编号、复制模板、登记。另一个仍为候选。 |
| 要求试写一段，或只改已有作品的一句话 | 试写只立必要的情境和声音，标探索稿。改一句从原句、上下文和文风入手，只在指代或情节确有歧义时补读。 |
| 章稿已存而摘要未更新。之后发现更早的章也被重写 | 从待同步项进入已存章，按照实际稿次补摘要。再追早章改掉的知情时间、动机或伏笔到依赖它们的后章。核实完才推进基线。 |
| 插章、改书名，同时另一会话在改后章 | 保留作品编号与原章节 ID，插章另取新 ID，调整显示名和展示顺序。合并前比两边基线，合并后读相邻及依赖章，核对事件能否接上。 |
| 技能下载受限，或运行时没有发现技能 | 将实际能力、失败或未验证环节写入技能说明，沿普通 Markdown 入口完成相同的策划或审读。详见[技能使用与恢复](skills.md)。 |
| 润色时碰到有意反复的长句，句中人物说了谎 | 对照视角与上下文判断反复承载的情绪、谎言影响了谁的认识。保留有效节奏与知情边界，仅修有明确问题的措辞。详见[文风审校](prose-style.md)。 |
