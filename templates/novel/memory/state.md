# 接续状态

交接或收到“继续”时从这里定位工作。只保留足够完成下一项动作的短摘要。下表随阶段替换旧值，长期决定移入[决定记录](decisions.md)。

| 项目 | 当前值 | 填写提示 |
| --- | --- | --- |
| 阶段和本轮任务 | 待填 | 写出委托范围、交付形式及完成条件。 |
| 最近完成位置 | 尚无 | 精确到文件、章节 ID、场景或小节及稿次。写到一半则注明断点。 |
| 接续要点 | 尚无 | 记眼下制约下一步的动作、关系或未知项；需要措辞时给原文位置。 |
| 已同步基线 | 尚无 | 指明核对过的源文件与稿次、对应的索引或记录范围。可引用能找回的实际提交，未提交的稿注明“工作稿”。 |
| 未同步事项 | 尚无 | 写明哪份源稿从哪一版变到哪一版、哪些摘要／事实／后续章待查、已完成哪一步。 |
| 下一步 | 待填 | 写一项可直接执行的动作及目标位置；若委托覆盖多章，保留尚余范围。 |

## 如何中断和恢复

1. 跨文件修改前，在“未同步事项”划出范围、来源及依据版本。大幅覆盖前核实旧稿可恢复。正文或基础设定写好后先保留它，再同步[章节索引](../chapters/README.md)、[连续性](continuity.md)、[后续计划](../planning/chapters.md)及重要决定。
2. 重新接手时检查待办、相关文件的当前内容和稿次。已有 Git 基线可比较差异；工作稿则核对原文、标识和可用快照。即使上次停在书末，早章有改也要沿该章的揭示、道具或人物选择追查受影响的位置。稿次相同但内容有分歧时以实际差异启动核对。
3. 保留已写成果，补齐缺失同步。核对完才推进“已同步基线”，删去本轮已处理的待办，刷新接续位置和下一步；阶段变化时更新仓库作品索引。局部错字可直接处理。

**自检**　接手者能找到最后实际写下的一段吗？能分辨已经核对的资料与尚待核对的资料，并沿来源找回依据吗？
